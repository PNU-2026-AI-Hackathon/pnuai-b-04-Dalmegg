# 생성형 AI 활용 내역

## 1. 활용한 AI 도구

본 프로젝트에서는 요구사항 정리, 설계 검토, 프론트엔드·백엔드 구현, 테스트, 문서화, 발표자료 제작 과정에서 생성형 AI를 개발 보조 도구로 활용했다. AI는 반복 코드 작성, 대안 탐색, 오류 원인 분석, 문서 초안 작성을 지원했으며, 최종 설계·구현·병합 결정은 개발팀이 수행했다.

| 도구 | 활용 목적 |
| :--- | :--- |
| Claude | PM 관점의 요구사항 정리, 기능 단위 작업 분해, 구현 우선순위 검토, 발표 흐름과 문서 구성 초안 작성 |
| Claude Code | 프론트엔드·백엔드 코드 초안 작성, 오류 원인 분석, 리팩터링 제안, 테스트 항목과 예외 상황 점검, API 문서 작성 |
| ChatGPT | 작물 생육 기준, 센서·스마트팜 관련 도메인 자료 조사, 출처 후보 탐색, 설명 문구와 문서 초안 작성 |
| Figma | 화면 구조, 디자인 시안, 발표자료 시각 구성 정리 |
| Claude Design | 발표자료와 UI 시안의 레이아웃·카피·시각 구성 아이디어 도출 |

AI가 제안한 내용 중 서비스 정책, 사용자 권한, 데이터 변경 규칙, 센서값 해석 기준, 관수 추천의 적용 범위는 팀원이 직접 판단했다. 운영 서버 계정, 비밀키, 실제 배포 환경 설정, 프로덕션 DB에 대한 파괴적 작업, 최종 기능 판정은 AI에 맡기지 않았다.

## 2. 활용 범위

| 영역 | 활용 내용 |
| :--- | :--- |
| UI/UX | 운영자 Web과 소비자 App의 화면 구조, 상태별 안내 문구, 반응형 UI 초안 작성 |
| Backend | FastAPI Route, Pydantic Schema, SQLAlchemy Model·Service 검토 및 인증·재고·예약·MQTT 처리 보조 |
| Frontend 연동 | React Web과 Flutter App의 REST API 연결, JWT 갱신, 오류·Loading·Mock/Fallback 상태 처리 |
| 테스트·디버깅 | API와 동시성 Test Case 작성, Type Error·Lint·Build Error 분석, 변경 영향 범위 점검 |
| 문서화 | 실행 방법, API 흐름, 실제 구현 상태를 Repository 코드 기준으로 정리 |

개인정보, 인증 비밀값, 운영 Database 정보는 Prompt에 입력하지 않았으며, AI가 제안한 코드를 검토 없이 배포하지 않았다.

## 3. AI 생성 코드의 검증·수정 방식

**요구사항 및 계약 대조** - AI가 생성한 코드가 프로젝트 요구사항, 기존 API 명세, 데이터 모델, 프론트엔드 연동 방식, 센서 통신 형식과 일치하는지 확인했다. 기존 코드와 충돌하거나 기능 범위를 벗어나는 제안은 반영하지 않았다.

**코드 리뷰 및 보완** - 팀원이 입력값 검증, 예외 처리, 인증·권한, 비밀정보 노출 가능성, 오류 발생 시 폴백을 검토했다. 프로젝트 구조에 맞지 않는 코드는 라우트·스키마·서비스 계층으로 다시 나누고, 응답 필드명과 예외 메시지를 프론트엔드 사용 방식에 맞게 수정했다.

**실행·테스트 검증** - 프론트엔드, 백엔드, 센서 연동 구성요소를 실제 실행해 정상 입력과 오류 입력을 확인했다. 백엔드는 `pytest`로 인증, 상점, 꽃 재고, 리뷰, 찜, 계란껍질 수거, 주문, 꽃다발 주문, 체험 예약, 관리자 예약 관리, 채팅, 센서, 대시보드, AI 생육 프로토타입 기능을 검증했다. 프론트엔드는 화면 렌더링, 라우팅, API 응답 처리, 폼 입력과 예외 상태를 직접 확인했다.

**상태 변경 검증** - 단순히 응답 코드만 확인하지 않고 DB 상태와 화면 표시가 실제로 맞게 바뀌는지 확인했다. 주문 생성 후 재고가 감소하는지, 예약 취소 후 좌석이 복구되는지, 리뷰 작성 후 상점 평점과 리뷰 수가 동기화되는지, MQTT 센서 메시지가 중복 저장되지 않는지 확인했다. 센서값, 작물별 기준, 환경 적합도와 관수 추천 결과는 재현 가능하고 상식적인 범위인지 다시 검토했다.

**수정 후 재검증** - 불일치, 보안 위험, 성능 문제, 화면 깨짐이 발견되면 AI 제안을 그대로 쓰지 않고 팀원이 직접 수정한 뒤 같은 시나리오를 다시 시험했다. AI 생성 결과는 팀의 검토·수정·검증을 거친 뒤에만 저장소에 반영했다.
